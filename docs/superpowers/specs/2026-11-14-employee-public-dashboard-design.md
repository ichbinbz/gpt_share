# 员工公开查询页设计

目标：同一页提供免查询令牌的官方账号额度与逐模型 Token 用量、新员工申请、以及本人令牌查询。

已选方案：客户端从 Codex 会话日志的 `turn_context.payload.model` 与后续 `token_count` 累计增量，按模型只上报数值。Broker 按设备的有效租约归属官方账号，累计每账号每模型 Token；公开页只返回账号登录用户名、额度窗口、模型健康和汇总数值。模型历史数据从客户端升级后开始积累，既有未标模型的历史数据不反推。

申请：员工提交姓名和工号，管理员在现有鉴权管理页看到待审申请并点击同意；同意后创建该员工的设备令牌。员工在公开页凭姓名和工号查询。用户明确选择仅用这两项领取，接受知情者可能冒领的风险。接口继续限速，不向公开状态列表暴露申请人资料或令牌。已有用户名与工号查询表单嵌入同页。

实现约束：Broker 仅监听回环地址；公开额度响应必须采用字段白名单，不能泄露邮箱、账号 ID、令牌、员工信息或原始官方接口数据。管理员审批需要现有管理员令牌。状态和用量持久化原子写入，客户端按会话绝对累计值上报以便重复扫描幂等。

后续界面与排行：员工页沿用管理员页深色视觉，桌面端每个账号一行；7 天额度余量、总 Token、各模型用量和可用状态以单行颜色标签呈现。Windows 账号选择窗口与 Linux 终端账号列表提示员工查询入口。管理员账号卡片显示官方当前 7 天窗口中客户端上报 Token 增量最多的 5 名员工，按 15 分钟时间桶累计，历史账号归属不回填。
